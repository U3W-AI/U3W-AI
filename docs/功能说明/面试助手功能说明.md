# 第一部分：用户使用指南

> **摘要**：本章节介绍如何找到并使用面试助手，无需了解技术细节。

### 1.1 功能简介

**面试助手** 是您的企业微信智能工作伙伴。它连接了公司内部的面试数据库，您只需在聊天框像对话一样发送指令，即可实时获取候选人信息、简历摘要和面试安排。所有敏感信息（如手机号）均会自动打码保护。

### 1.2 如何在企业微信添加助手

面试助手通常由企业管理员预先配置好。用户可以通过以下两种方式使用：

**方式一：单聊使用**

1. 打开企业微信手机端或电脑端。
2. 点击底部的“**通讯录**”。
3. 在“**我的企业**”或“**其他联系人**”分类下找到“**面试助手**”应用。
4. 点击进入，选择“发消息”即可开始交互。

**方式二：群聊使用 (推荐)**

1. 进入面试官群或 HR 沟通群。
2. 点击群聊设置（右上角 `...`）。
3. 选择 **“添加群机器人”**。
4. 如果在列表中看到了“面试助手”，直接添加即可。
5. *注：如果未直接显示，请让管理员将应用的“接收消息API”开启并发布到群。*

### 1.3 常用指令与场景

**场景 A：HR 每日早会汇报**

- **需求**：快速查看今天有哪些人来面试，安排接待和会议室。

- **指令**：`@面试助手 今日面试` (单聊直接发送 `今日面试`)

- **回复示例**：

  Plaintext

  ```
  今日已记录面试：2 人
  1. 牧文｜南开大学 大四｜Frontend, React
  2. 裴杰超｜武汉大学 大三｜Node.js, MongoDB
  ```

**场景 B：面试官快速预览**

- **需求**：在面试开始前 5 分钟，快速回顾最近录入的候选人详情。

- **指令**：`@面试助手 查看最近 3` (数字可改为 1-5)

- **回复示例**：

  Plaintext

  ```
  最近 3 条面试记录：
  1. 姓名 牧文｜南开大学 大四
     技术栈 Frontend, React, Vue
     摘要 深入理解计算机系统...
     手机号 139xxxx1810
     面试时间 01-23 12:06
  ...
  ```

# 第二部分：运维与部署指南

> **摘要**：本章节详细说明如何在企业微信管理后台创建应用，并完成服务器的对接部署。

### 2.1 企业微信后台配置 (核心步骤)

在启动 Java 代码前，必须先在企业微信后台获取必要的凭证。

1. **登录后台**：访问 [企业微信管理后台](https://www.google.com/search?q=https://work.weixin.qq.com/wework_admin/login_page_wx)。
2. **创建应用**：
   - 点击 **“应用管理”** -> **“应用”** -> **“创建应用”**。
   - 应用名称：填入“面试助手”。
   - 可见范围：选择需要使用该功能的部门（如 HR 部、技术部）。
   - 创建完成后，记录下 **AgentId** and **Secret**。
3. **配置 API 接收消息** (关键)：
   - 在应用详情页，找到 **“接收消息”** -> **“设置 API 接收”**。
   - **URL (服务器地址)**: 填入您的公网可访问地址，例如 `http://your-server-ip:8080/api/wechat`。
   - **Token**: 点击随机获取，**记录下来**（对应配置文件 `wechat.token`）。
   - **EncodingAESKey**: 点击随机获取，**记录下来**（对应配置文件 `wechat.aes-key`）。
   - **保存**：点击保存时，企业微信会向您的 URL 发送一个 GET 请求进行验证。**请确保此时您的 Java 服务已经启动**（或先配置好 Nginx 转发），否则保存会失败。
4. **企业 ID**:
   - 在“我的企业” -> “企业信息”最下方找到 **CorpId**，**记录下来**。

### 2.2 服务端配置与启动

#### 1. 配置文件修改

修改 `src/main/resources/application.yml`，填入上一步获取的信息：

YAML

```
wechat:
  corp-id: "ww123456..."       # 2.1 步获取的 CorpId
  token: "89s7d8..."           # 2.1 步设置的 Token
  aes-key: "M4O1..."           # 2.1 步设置的 EncodingAESKey

spring:
  datasource:
    # 数据库连接配置
    url: jdbc:mysql://localhost:3306/interview_bot?useUnicode=true&characterEncoding=utf8
    username: root
    password: your_password
```

#### 2. 启动服务

本项目已集成至 `WxFbsir-admin`，请通过主程序启动：

Bash

```
# 进入主模块
cd WxFbsir-admin
# 启动
mvn spring-boot:run
```

### 2.3 故障排查 (FAQ)

**Q1: 在企业微信后台点击“保存”API 设置时提示“请求地址URL校验失败”？**

- **原因**：服务未启动、防火墙未放行端口、或 URL 外网不可访问。
- **解决**：
  1. 确保 Java 服务已启动且无报错。
  2. 确保 URL 在浏览器中直接访问能通（显示 verify fail 或其他提示，而不是 404/无法连接）。
  3. 检查 `token` 和 `aes-key` 是否与代码配置完全一致。

**Q2: 发送指令后机器人没反应？**

- **原因**：企业微信签名校验失败或 IP 白名单拦截。
- **排查**：查看后端日志，搜索 `[微信回调]`。如果提示 `签名不匹配`，请检查 Token。同时检查企业微信后台是否配置了“企业可信 IP”。

**Q3: 为什么“查看最近 10”提示不支持？**

- **原因**：为了避免群聊消息过长刷屏，代码硬性限制了 `limit <= 5`。

# 第三部分：技术开发指南

> **摘要**：本章节面向开源贡献者，详细说明系统架构、代码实现细节及二次开发规范。

### 3.1 核心架构与模块

本项目遵循标准的 Spring Boot 分层架构，严格遵守 `WxFbsir-business` 模块划分规范。

Plaintext

```
com.wx.fbsir.business/interviewbot
├── controller/
│   └── WechatBotController.java  # 核心入口：处理 /api/wechat 回调，含 URL 验证与消息路由
├── service/
│   └── InterviewService.java     # 业务逻辑：指令解析、参数校验、结果组装
├── mapper/
│   └── InterviewMapper.java      # 数据层：MyBatis 注解式 SQL
├── domain/
│   └── InterviewRecord.java      # 实体类：含数据脱敏方法
├── utils/
│   └── WXBizJsonMsgCrypt.java    # 协议层：复刻官方算法，处理 AES-256 加解密
```

**数据流转图**：

Plaintext

```
用户发送消息 -> 企业微信服务器 -> /api/wechat (POST)
       -> WechatBotController (验证签名)
       -> WXBizJsonMsgCrypt (解密 JSON)
       -> 指令清洗 (去除 @机器人)
       -> InterviewService (业务查询)
       -> InterviewMapper (SQL 查询)
       -> InterviewRecord (数据脱敏)
       -> WXBizJsonMsgCrypt (加密回复)
       -> 返回企业微信 -> 用户收到回复
```

### 3.2 业务逻辑实现

#### 1. 消息加解密 (Utils)

核心类 `WXBizJsonMsgCrypt` 使用 Java 原生 `java.util.Base64` 替代 Apache Commons Codec，避免了 Tomcat 依赖冲突。实现了 `VerifyURL` (GET 验证) 和 `DecryptMsg`/`EncryptMsg` (POST 交互)。

#### 2. 指令解析 (Controller)

在 `WechatBotController` 中实现指令的正则匹配：

Java

```
// 匹配 "查看最近 N" (支持中间包含空格)
java.util.regex.Pattern pattern = java.util.regex.Pattern.compile("^查看最近\\s*(\\d+)$");
```

#### 3. 数据查询 (Mapper)

使用注解式 SQL，包含时间过滤逻辑以防止未来时间的测试数据干扰：

Java

```
@Select("SELECT * FROM interview_record WHERE interview_time <= NOW() ORDER BY interview_time DESC LIMIT #{limit}")
List<InterviewRecord> selectRecentRecords(int limit);
```

### 3.3 数据结构与隐私安全

#### 1. 数据库设计

表名：`interview_record`

| **字段名**       | **类型**     | **必填** | **说明**              |
| ---------------- | ------------ | -------- | --------------------- |
| `id`             | BIGINT       | 是       | 主键 ID               |
| `name`           | VARCHAR(32)  | 是       | 候选人姓名            |
| `tech_stack`     | VARCHAR(255) | 否       | 技术栈                |
| `summary`        | TEXT         | 否       | 简历摘要              |
| `phone_number`   | VARCHAR(32)  | 否       | **敏感字段** (需脱敏) |
| `id_card`        | VARCHAR(32)  | 否       | **敏感字段** (需脱敏) |
| `interview_time` | DATETIME     | 是       | 面试时间 (索引)       |
| `create_time`    | DATETIME     | 是       | 创建时间              |

#### 2. 隐私脱敏策略

为防止群聊中泄露隐私，`InterviewRecord` 实体类内置了掩码处理逻辑。

- **手机号**：保留前3后4 `138xxxx8000`

  Java

  ```
  return phone.replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1xxxx$2");
  ```

- **身份证**：保留前6后4 `110101xxxxxxxx1234`

  Java

  ```
  return id.replaceAll("(\\w{6})\\w+(\\w{4})", "$1xxxxxxxx$2");
  ```

### 3.4 日志规范

- `INFO`: 关键业务节点（如收到指令、处理成功）。

- `ERROR`: 异常堆栈（如解密失败、数据库断连）。

- `DEBUG`: 生产环境建议关闭，防止日志中打印原始加密报文。
