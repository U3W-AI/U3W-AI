## 一、产品简介

**简历助手**是一款面向开发者与求职者的智能简历管理工具，集成了 **简历上传、AI 解析、短链分享、访问码控制与访问数据统计** 等功能。

通过本系统，用户可以：

- 一次上传简历，自动结构化解析

- 生成专属简历短链接，便于对外分享

- 通过访问码控制简历访问权限

- 实时查看简历访问数据与日志

- 将简历从“文件”升级为“可运营资产”

##   **📊 数据库设计**

### 表1：cv_storage（简历存储与解析结果表）

存储用户上传的简历及AI解析结果。

```sql
create table cv_storage
(
    id                    bigint auto_increment comment '主键ID'
        primary key,
    user_id               bigint                             not null comment '用户ID',
    cv_id                 varchar(64)                        not null comment '简历ID（自动生成）',
    cv_name               varchar(255)                       not null comment '简历名称',
    name                  varchar(100)                       null comment '解析后的姓名',
    phone                 varchar(32)                        null comment '解析后的手机号',
    mail                  varchar(100)                       null comment '解析后的邮箱',
    shortlink             varchar(255)                       not null comment '简历访问短链接',
    parse_content         longtext                           null comment '解析内容（来自腾讯元器智能体）',
    process_status        tinyint  default 0                 not null comment '处理状态：0-处理中，1-已完成，2-失败',
    file_url              varchar(512)                       not null comment '简历文件实际存储位置',
    available             tinyint  default 1                 not null comment '是否启用：0-禁用，1-启用',
    create_time           datetime default CURRENT_TIMESTAMP not null comment '创建时间',
    update_time           datetime default CURRENT_TIMESTAMP not null on update CURRENT_TIMESTAMP comment '更新时间',
    create_by             varchar(64)                        null comment '创建者',
    update_by             varchar(64)                        null comment '更新者',
    remark                varchar(500)                       null comment '备注',
    access_code_available tinyint  default 0                 not null comment '是否启用访问码：0-禁用，1-启用',
    deadline              datetime                           null comment '截止时间',
    constraint uk_cv_id
        unique (cv_id),
    constraint uk_shortlink
        unique (shortlink)
)
    comment '简历存储与解析结果表';

create index idx_user_id
    on cv_storage (user_id);
```

### 表2：cv_access_code（简历访问码表）

存储简历访问码信息。

```sql
create table cv_access_code
(
    id               bigint auto_increment comment '主键ID'
        primary key,
    shortlink        varchar(255)                       not null comment '简历访问短链接',
    access_code      varchar(32)                        not null comment '简历访问码',
    accessible_count int      default 1                 not null comment '可访问次数',
    deadline         datetime                           null comment '截止时间',
    available        tinyint  default 1                 not null comment '是否启用：0-禁用，1-启用',
    create_time      datetime default CURRENT_TIMESTAMP not null comment '创建时间',
    update_time      datetime default CURRENT_TIMESTAMP not null on update CURRENT_TIMESTAMP comment '更新时间',
    del_flag         tinyint  default 0                 not null comment '删除标识：0-不删除，1-已删除',
    constraint uk_shortlink_access_code
        unique (shortlink, access_code)
)
    comment '简历访问码表';

create index idx_shortlink
    on cv_access_code (shortlink);
```

### 表3：cv_monitor（简历访问监控表）

存储简历访问数据信息。

```sql
create table cv_monitor
(
    id          bigint auto_increment comment '主键ID'
        primary key,
    shortlink   varchar(255)                       not null comment '简历访问短链接',
    date        date                               not null comment '访问日期',
    count       int      default 0                 not null comment '访问量',
    create_time datetime default CURRENT_TIMESTAMP not null comment '创建时间',
    update_time datetime default CURRENT_TIMESTAMP not null on update CURRENT_TIMESTAMP comment '更新时间',
    constraint uk_shortlink_date
        unique (shortlink, date) comment '短链接和日期唯一索引'
)
    comment '简历访问监控表';
```

### 表4：cv_access_log（简历访问日志表）

存储简历访问日志信息。

```sql
(
```

### ⚠️ 重要配置：域名配置

在使用文档解析助手之前，**如果使用内网穿透，必须配置域名**，否则腾讯元器智能体无法访问上传的文档。

#### 配置方式一：修改配置文件

1. 打开配置文件：`FBSir-admin/src/main/resources/application.yml`

2. 找到 `fbsir` 配置部分，修改 `domain` 配置项：

   ```
   fbsir:
     # 域名配置（用于拼接完整URL）
     # 开发环境：http://localhost:8080
     # 生产环境/内网穿透：使用实际访问域名（如 http://your-domain.com）
     domain: http://abc.com
   ```

3. 将 `http://abc.com` 替换为您的实际公网访问地址

4. 保存文件并重启后端服务

#### 配置方式二：使用环境变量（推荐生产环境）

设置环境变量 `WXFBSIR_DOMAIN` 为您的公网访问地址：

**Windows:**

```
set WXFBSIR_DOMAIN=http://abc.com
```

**Linux/Mac:**

```
export WXFBSIR_DOMAIN=http://abc.com
```

#### 为什么需要配置？

- 文档上传后，系统会生成一个访问URL（如 `http://localhost:8080/profile/upload/xxx.pdf`）
- 腾讯元器智能体运行在云端，无法访问本地的 `localhost:8080`
- 系统会自动将 `localhost:8080` 替换为配置的域名，使智能体能够通过公网访问文档
- 如果不配置，智能体将无法读取文档内容，导致解析失败

### ⚙️ 文件上传配置(同文件解析)

文档上传功能依赖系统的文件上传配置，需要在配置文件中设置上传路径和大小限制。

#### 配置文件位置

```
FBSir-admin/src/main/resources/application.yml` 或 `application.properties
```

#### 配置示例

**application.yml:**

```
spring:
  servlet:
    multipart:
      enabled: true
      max-file-size: 10MB        # 单个文件最大大小
      max-request-size: 10MB      # 请求最大大小
  web:
    resources:
      static-locations: file:profile/  # 静态资源路径

# 文件上传路径
file:
  upload:
    path: profile/
```

**application.properties:**

```
spring.servlet.multipart.enabled=true
spring.servlet.multipart.max-file-size=10MB
spring.servlet.multipart.max-request-size=10MB
spring.web.resources.static-locations=file:profile/
file.upload.path=profile/
```

#### 注意事项

- 确保 `profile/` 目录存在且有写入权限
- 文件上传路径需要与内网穿透域名配置一致
- 上传的文件保存在 `profile/upload/` 目录下
- 腾讯元器智能体通过 `http://内网穿透域名/profile/upload/xxx.pdf` 访问文件

### ⚙️ 数据库配置

文档解析助手需要连接MySQL数据库，需要在配置文件中设置数据库连接信息。

#### 配置文件位置

```
FBSir-admin/src/main/resources/application.yml` 或 `application.properties
```

#### 配置示例

**application.yml:**

```
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/fbsir?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8
    username: root
    password: your_password
```

**application.properties:**

```
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.datasource.url=jdbc:mysql://localhost:3306/fbsir?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8
spring.datasource.username=root
spring.datasource.password=your_password
```

#### 注意事项

- 确保MySQL服务已启动
- 数据库 `fbsir` 需要提前创建
- 执行 `sql/fbsir.sql` 初始化数据库表结构
- 根据实际情况修改数据库地址、端口、用户名和密码
- 建议使用连接池（如HikariCP）提高性能

#### 配置示例

```
server:
  port: 8080
```

**MySQL数据库端口（application.yml）:**

```
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/fbsir
```

**Apache Tika服务器端口:**

```
java -jar tika-server-standard-3.2.3.jar --port 9998
```

#### 注意事项

- 确保所有端口未被其他程序占用
- 如果端口被占用，可以修改为其他可用端口
- 修改端口后需要同步更新相关配置（如内网穿透域名配置）
- 使用 `netstat -ano | findstr 端口号` 检查端口占用情况（Windows）
- 使用 `lsof -i:端口号` 检查端口占用情况（Linux/Mac）

### 1. 配置智能体

首次使用前，需要配置腾讯元器智能体：

1. 点击页面右上角的"配置智能体"按钮

2. 在工作流中选择新建->批量导入，将export-简历解析工作流.zip导入

3. 修改请求URL

   - 找到接口链接
   - 原始地址可能是：`http://xxx:8080/resume/ParsedContent`
   - 修改为您的公网地址：`http://您的公网IP:8080/resume/ParsedContent`

   ![image-20260213101231233](C:\Users\26279\AppData\Roaming\Typora\typora-user-images\image-20260213101231233.png)

4. 填写以下信息：

   - **智能体ID（appid）**：从腾讯元器智能体配置→应用发布→服务状态→体验链接中截取
   - **智能体名称**：自定义名称，如"文档解析助手"
   - **API密钥（apikey）**：从应用发布→API管理中复制
   - **API端点**：默认为 `https://yuanqi.tencent.com/openapi/v1/agent/chat/completions`

5. 点击"保存"按钮

#### 获取appid和apikey的详细步骤

**步骤1：获取appid（智能体ID）**

1. 登录腾讯元器平台
2. 进入"文档解析助手智能体"
3. 点击左侧菜单"应用发布"
4. 选择"服务状态"标签页
5. 在"体验链接"中找到URL，例如：`https://yuanqi.tencent.com/chat/assistant/1234567890abcdef`
6. 从URL中截取appid部分：`1234567890abcdef`

**步骤2：获取apikey（API密钥）**

1. 在"应用发布"页面中，点击"API管理"标签页
2. 找到API密钥（apikey）字段
3. 点击"复制"按钮复制apikey
4. 将复制的apikey粘贴到配置表单中

**示例：**

```
体验链接：https://yuanqi.tencent.com/chat/assistant/1234567890abcdef
                                                     ↑
                                                  appid（截取这部分）

API管理页面：
┌─────────────────────────────────────┐
│ API密钥：sk-abc123def456ghi789       │
│              [复制]                 │
└─────────────────────────────────────┘
         ↑
      apikey（复制这部分）
```
