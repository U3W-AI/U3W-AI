# AIGC 输出物管理功能说明

AIGC 输出物管理功能，用于将 AI 会话中的探讨结果沉淀为结构化内容，并支持编辑、导出及推送等能力，提升结果的可复用性与业务价值。

## 一、功能概述

本功能基于 AIGC 会话能力扩展，实现“输出物”管理闭环，主要包括：

1. **输出物生成**：基于会话内容自动生成结构化摘要
2. **输出物编辑**：支持用户对生成内容进行修改
3. **输出物保存**：支持持久化保存至会话数据
4. **导出能力**：支持 Markdown 与 JSON 导出
5. **Webhook 推送**：支持推送至企业微信等外部系统
6. **权限控制**：基于菜单权限控制功能访问
7. **异常处理**：完善的边界与异常处理机制
8. **日志记录**：详细的操作日志记录

------

## 二、使用场景

- AI 探讨结果沉淀为结构化内容
- 输出物编辑与二次加工
- 导出文档用于汇报或记录
- 推送至企业微信、自动化系统等外部工具
- 提升 AI 输出结果的复用能力

## 四、接口说明

### 后端接口

| 接口地址                                  | 请求方式 | 权限     | 说明         |
| ----------------------------------------- | -------- | -------- | ------------ |
| `/aigc/output/generate`                   | GET      | 登录用户 | 生成输出物   |

| ------ | ------------ | ------- | ------------------------------ |
| 1526   | 生成输出物   | 按钮(F) | business:output:generate       |
| 1527   | 导出Markdown | 按钮(F) | business:output:exportMarkdown |
| 1529   | 推送Webhook  | 按钮(F) | business:output:pushWebhook    |
| 1530   | 保存输出物   | 按钮(F) | business:output:save           |

### 权限说明

- 采用按钮级权限控制
- 未授权用户不可执行相关操作
- 需执行 SQL 脚本后生效

## 六、核心特性

### 1. 结构化输出

将 AI 会话结果转为统一结构：

生成规则：

```
问题：userPrompt
结论摘要：data.answer
```

示例：

```
问题：如何部署AI服务
结论摘要：建议使用Docker部署并通过Nginx进行反向代理
```

权限配置SQL

```
-- 生成输出物

insert into sys_menu values('1526', '生成输出物', '153', '1', '', '', '', '', 1, 0, 'F', '0', '0', 'business:output:generate', '#', 'admin', sysdate(), '', null, '生成输出物权限');

-- 导出Markdown

insert into sys_menu values('1527', '导出Markdown', '153', '2', '', '', '', '', 1, 0, 'F', '0', '0', 'business:output:exportMarkdown', '#', 'admin', sysdate(), '', null, '导出Markdown权限');

-- 导出JSON

insert into sys_menu values('1528', '导出JSON', '153', '3', '', '', '', '', 1, 0, 'F', '0', '0', 'business:output:exportJson', '#', 'admin', sysdate(), '', null, '导出JSON权限');

-- 推送Webhook

insert into sys_menu values('1529', '推送Webhook', '153', '4', '', '', '', '', 1, 0, 'F', '0', '0', 'business:output:pushWebhook', '#', 'admin', sysdate(), '', null, '推送Webhook权限');

-- 保存输出物

insert into sys_menu values('1530', '保存输出物', '153', '5', '', '', '', '', 1, 0, 'F', '0', '0', 'business:output:save', '#', 'admin', sysdate(), '', null, '保存输出物权限');

```

### 5. 异常处理

覆盖以下场景：

- 会话不存在
- 会话归属错误
- AI结果为空
- 输出物不存在
- 导出失败
- Webhook地址非法
- Webhook推送失败

统一的异常处理机制，确保错误信息清晰：

例如：

```
try {
    // 业务逻辑
} catch (Exception e) {
    logger.error("[输出物推送] 接口异常 - sessionId: {}, format: {}, webhookUrl: {}, 错误类型: {}, 错		误信息: {}",params.get("sessionId"),
    params.get("format"),params.get("webhookUrl"),
    e.getClass().getSimpleName(), e.getMessage());
    return AjaxResult.error("操作失败: " + e.getMessage());
}
```

## 十一、注意事项

1. 输出物基于会话生成，需确保会话存在
2. Webhook 地址需合法
3. 导出前需存在输出物内容
4. SQL 权限需提前执行
5. 多次生成输出物会覆盖旧数据
6. Deepseek和gitee同时对话时，Deepseek优先。
