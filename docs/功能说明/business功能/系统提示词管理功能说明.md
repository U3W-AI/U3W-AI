# 系统提示词管理功能说明

系统提示词管理功能，支持工作流提示词的增删改查，用于AI工作流的系统提示词配置和管理。

## 功能概述

系统提示词管理功能提供了一套完整的提示词管理解决方案，主要包括：

1. **提示词管理**：支持系统提示词的新增、查询、修改、删除
2. **版本控制**：支持提示词版本管理，便于追踪变更历史
3. **分类管理**：支持按分类组织提示词
4. **状态控制**：支持启用/禁用提示词
5. **工作流集成**：提供接口供工作流调用获取提示词内容

---

## 使用场景

- **AI工作流配置**：为不同的AI工作流配置系统提示词
- **提示词版本管理**：管理提示词的多个版本，支持回滚
- **提示词分类**：按业务场景分类管理提示词
- **动态提示词切换**：根据业务需求动态切换不同的提示词

## 配置说明

### 1. 数据库表创建

确保数据库中存在 `system_prompts` 表：

```sql
CREATE TABLE `system_prompts` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `name` varchar(255) NOT NULL COMMENT '提示词名称',
  `content` text NOT NULL COMMENT '提示词内容',
  `description` varchar(500) DEFAULT NULL COMMENT '描述',
  `version` varchar(50) DEFAULT '1.0' COMMENT '版本号',
  `status` tinyint(1) NOT NULL DEFAULT '1' COMMENT '状态：1-启用，0-禁用',
  `category` varchar(100) DEFAULT NULL COMMENT '分类',
  `tags` varchar(500) DEFAULT NULL COMMENT '标签（逗号分隔）',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_name_version` (`name`,`version`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='系统提示词表';
```

### 数据表：`system_prompts`

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT | 主键ID |
| name | VARCHAR(255) | 提示词名称（必填） |

| description | VARCHAR(500) | 描述信息 |
| version | VARCHAR(50) | 版本号，默认1.0 |

| update_time | DATETIME | 更新时间 |

### 唯一约束

- `name` + `version` 组合唯一，确保同一提示词的不同版本可以共存

## 使用示例

### 1. 管理后台操作

在管理后台的"系统提示词"页面：
1. 点击"新增"按钮创建新的提示词
2. 填写提示词名称、内容、描述等信息
3. 设置版本号和分类
4. 选择启用状态
5. 保存配置

### 2. 工作流调用

工作流通过接口获取提示词内容：

```java
// 获取提示词内容
String promptContent = systemPromptService.selectSystemPromptById(1L).getContent();
```

或通过HTTP接口：

```http
GET /business/prompt/system?id=1
```

### 3. 前端调用示例

```javascript
import { getSystemPrompt, updateSystemPrompt } from '@/api/business/systemPrompt/systemPrompt'

// 获取提示词
const res = await getSystemPrompt(1)
if (res.code === 200) {
  console.log(res.data.content)
}

// 更新提示词
await updateSystemPrompt({
  id: 1,
  name: '默认提示词',
  content: '新的提示词内容...',
  version: '1.1'
})
```

## 字段说明

### 提示词名称（name）
- 用于标识提示词的名称
- 同一提示词的不同版本使用相同的名称
- 建议命名规范：`场景_用途`，如 `daily_assistant_system`

### 提示词内容（content）
- 实际的提示词文本内容
- 支持长文本，使用TEXT类型存储
- 可以包含变量占位符，如 `{user_name}`

### 版本号（version）
- 用于管理提示词的版本
- 建议使用语义化版本，如 `1.0`、`1.1`、`2.0`
- 同名提示词的不同版本可以共存

### 分类（category）
- 用于对提示词进行分组管理
- 建议分类：`daily_assistant`、`document_parse`、`code_review` 等

### 标签（tags）
- 用于给提示词打标签
- 多个标签使用逗号分隔，如 `ai,assistant,default`
- 便于后续搜索和筛选

### 状态（status）
- `true`：启用，可以被工作流调用
- `false`：禁用，不会被工作流调用

## 最佳实践

1. **命名规范**：使用有意义的名称，便于识别提示词用途
2. **版本管理**：修改提示词时创建新版本，保留历史版本
3. **分类管理**：按业务场景分类，便于管理
4. **状态控制**：测试中的提示词先禁用，确认无误后再启用
5. **内容备份**：定期导出提示词配置，防止数据丢失

---

## 注意事项

1. **唯一约束**：同一提示词的版本号不能重复
2. **内容长度**：提示词内容支持长文本，但建议不要过长以免影响性能
3. **工作流依赖**：删除提示词前确认没有工作流正在使用
4. **缓存策略**：工作流可能会缓存提示词内容，修改后可能需要重启工作流
