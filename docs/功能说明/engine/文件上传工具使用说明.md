## 1. 快速上手

> 阅读本节就够了，5分钟跑通第一个上传。

### 第一步：注入工具

```java
@Autowired
private FileDownloadUtil fileDownloadUtil;
```

### 第二步：一行完成文件上传

```java
// 完整流程：下载 → 校验 → 上传到AI平台 → 自动清理临时文件
FileDownloadUtil.UploadResult result = fileDownloadUtil.downloadAndUploadToPage(
    uploadedFileUrl,                                        // 文件的下载URL
    page,                                                   // Playwright页面
    (p, filePath) -> deepSeekUtil.uploadFile(p, filePath)   // 注入平台的上传逻辑
);

if (result.isSuccess()) {
    task.sendLog("文件上传成功");
} else {
    task.sendLog("上传失败: " + result.getErrorMessage());
}
```

### 第三步：处理错误（可选但推荐）

```java
if (!result.isSuccess()) {
    switch (result.getErrorType()) {
        case DOWNLOAD_FAILED -> task.sendLog("文件链接无法访问，请检查URL");
        case FILE_CORRUPTED, FILE_EMPTY -> task.sendLog("文件已损坏，请重新提供");
        case UPLOAD_FAILED -> task.sendLog("上传失败，以纯文本继续");
        default -> task.sendLog("处理失败: " + result.getErrorMessage());
    }
}
```

### 你只需要关心这两点

1. **提供平台的上传逻辑**（`PageFileUploader`）— 各平台已有对应 `uploadFile()` 方法
2. **检查 `result.isSuccess()`** — 工具负责下载、校验、重试、清理，你只接收结果

> **注意**：工具只保证「文件已送入页面」，不等待平台解析完成。
> 如需判断解析完成，见 [场景5：上传后等待解析完成](#场景5上传后等待平台解析完成)。

## 2. 场景指南

> 按你当前遇到的情况找对应代码，不需要从头看。

---

### 场景1：平台有标准上传按钮（最常见）

适用于 DeepSeek、Gitee AI 等平台已有 `uploadFile()` 方法的情况。

```java
UploadResult result = fileDownloadUtil.downloadAndUploadToPage(
    fileUrl, page,
    (p, filePath) -> deepSeekUtil.uploadFile(p, filePath),
    () -> deepSeekUtil.closeWebSearchButton(page)  // 上传前准备，可为null
);
```

---

### 场景2：需要多步点击才能触发文件选择器

**典型场景**：点击「附件图标」→ 弹出菜单 → 点击「上传本地文件」→ 文件选择器弹出。

```java
// 完整流程版（推荐）
UploadResult result = fileDownloadUtil.downloadAndUploadViaSteps(
    fileUrl, page,
    "li:text('上传本地文件')",                    // 最终触发文件选择器的元素
    null,                                         // 全局上传前准备，可为null
    p -> p.locator(".attach-icon").click(),       // 步骤1：点击附件图标
    p -> p.waitForTimeout(600)                    // 步骤2：等待菜单展开
);
```

已有本地文件时，只做上传：

```java
boolean ok = fileDownloadUtil.uploadViaSteps(
    page, localFilePath,
    "li:text('本地文件')",
    p -> p.locator("[aria-label='添加附件']").click(),
    p -> p.waitForTimeout(500)
);
```

> `fileChooserTriggerSelector` 是**最后点击的元素**（触发文件选择弹窗的那个）；前面的步骤顺序执行，单步失败会记日志后继续。

---

### 场景3：不清楚平台DOM结构，让工具自动探测

工具依次尝试：`input[type=file]` → 你提供的选择器 → 内置通用选择器（含中英文上传按钮）。

```java
// 完全自动
boolean ok = fileDownloadUtil.uploadViaDOM(page, localFilePath);

// 提供平台特有选择器优先尝试
boolean ok = fileDownloadUtil.uploadViaDOM(page, localFilePath, new String[]{
    "div.chat-toolbar button.upload",
    "[data-testid='file-upload-btn']"
});
```

---

### 场景4：平台上传逻辑不稳定，需要自动降级

平台专属逻辑失败时，自动切换到 DOM 通用方式：

```java
UploadResult result = fileDownloadUtil.downloadAndUploadWithFallback(
    fileUrl, page,
    (p, filePath) -> yuanBaoUtil.uploadFile(p, filePath),   // 优先
    () -> { /* 上传前准备 */ },
    new String[]{ "input.file-input", "button.attach-btn" } // 降级时的选择器
);
```

`uploader` 传 `null`，直接走 DOM 方式：

```java
UploadResult result = fileDownloadUtil.downloadAndUploadWithFallback(
    fileUrl, page, null, null, new String[]{ "input[type='file']" }
);
```

---

### 场景5：上传后等待平台解析完成

工具默认不等待解析，注入 `UploadCompletionChecker` 可轮询检测（每2秒检测一次，最多60秒）：

```java
UploadResult result = fileDownloadUtil.downloadAndUploadToPage(
    fileUrl, page,
    (p, filePath) -> deepSeekUtil.uploadFile(p, filePath),
    null,
    p -> p.locator("text=解析中").count() == 0   // true时停止轮询
);

// UPLOAD_TIMEOUT = 60秒内仍未完成，根据业务决定是否继续
if (result.getErrorType() == UploadResult.ErrorType.UPLOAD_TIMEOUT) {
    task.sendLog("文件仍在解析，继续发送消息");
}
```

复杂检测逻辑：

```java
UploadCompletionChecker checker = p -> {
    if (p.locator("text=解析中").count() > 0) return false;
    if (p.locator(".upload-error").count() > 0) return true;  // 出错也算完成，避免死等
    return p.locator(".file-tag").count() > 0;
};
```

---

### 场景6：先清除已上传文件，再重新上传

```java
// 删除第一个匹配到的文件
fileDownloadUtil.removeUploadedFile(page, new String[]{
    "button.file-delete-btn",
    "[aria-label='删除']"
});

// 删除所有已上传文件
int removed = fileDownloadUtil.removeAllUploadedFiles(page, "button.file-delete-btn");

// 重新上传
UploadResult result = fileDownloadUtil.downloadAndUploadToPage(newFileUrl, page, uploader);
```

---

### 场景7：接入全新AI平台（从零开始）

**第1步**：用自动探测确认上传入口能通

```java
String localPath = fileDownloadUtil.downloadFileWithRetry(testFileUrl);
boolean ok = fileDownloadUtil.uploadViaDOM(page, localPath);  // 看日志哪个选择器命中
fileDownloadUtil.cleanupTempFile(localPath);
```

**第2步**：根据日志确定平台的上传方式，选择封装

| 日志显示 | 对应方法 |
|---------|---------|
| `input[type=file] 直接设置成功` | 在 XxxUtil 实现 `uploadFile()`，用 `setInputFiles` |
| `自定义选择器触发成功` | 在 XxxUtil 用 `waitForFileChooser` + 对应选择器 |
| 所有策略失败 | 用 `uploadViaSteps()` 并逐步增加前置点击步骤 |

**第3步**：在 Controller 中调用 `downloadAndUploadToPage()`

---

### 场景8：只下载文件，自行控制上传

```java
String localPath = fileDownloadUtil.downloadFileWithRetry(fileUrl);
if (localPath == null) { return; }

UploadResult validate = fileDownloadUtil.validateDownloadedFile(localPath);
if (!validate.isSuccess()) {
    fileDownloadUtil.cleanupTempFile(localPath);
    return;
}

myCustomUploadLogic(page, localPath);
fileDownloadUtil.cleanupTempFile(localPath);  // 必须清理！
```

## 3. API 参考

### 3.1 方法速查

| 方法 | 说明 |
|------|------|
| `downloadAndUploadToPage(url, page, uploader)` | 完整流程（推荐入口） |
| `downloadAndUploadToPage(url, page, uploader, before)` | 同上 + 上传前准备 |
| `downloadAndUploadToPage(url, page, uploader, before, checker)` | 同上 + 异步完成检测 |
| `downloadAndUploadViaSteps(url, page, trigger, before, steps...)` | 完整流程 + 多步骤点击 |
| `downloadAndUploadWithFallback(url, page, uploader, before, selectors)` | 完整流程 + 自动降级 |
| `uploadViaDOM(page, filePath)` | DOM通用上传（自动探测） |
| `uploadViaDOM(page, filePath, selectors)` | DOM上传 + 自定义选择器 |
| `uploadViaSteps(page, filePath, trigger, steps...)` | 多步骤上传（已有本地文件） |
| `removeUploadedFile(page, selectors)` | 删除第一个匹配的已上传文件 |
| `removeAllUploadedFiles(page, selector)` | 批量删除所有匹配的已上传文件 |
| `downloadFileWithRetry(url)` | 带重试下载（推荐） |
| `downloadFile(url)` | 单次下载 |
| `validateDownloadedFile(filePath)` | 校验文件有效性 |
| `cleanupTempFile(filePath)` | 删除本地临时文件 |
| `encodeUrl(url)` | 编码URL中的中文字符 |

### 3.2 函数式接口

| 接口 | 签名 | 说明 |
|------|------|------|
| `PageFileUploader` | `boolean upload(Page, String)` | 平台专属上传逻辑 |
| `BeforeUploadAction` | `void execute()` | 上传前准备（如关闭冲突功能） |
| `UploadCompletionChecker` | `boolean isCompleted(Page)` | 异步完成检测，返回true停止轮询 |
| `UploadStep` | `void execute(Page) throws Exception` | 多步骤上传中的单步操作 |

### 3.3 UploadResult

```java
result.isSuccess()        // 是否成功
result.getErrorType()     // 错误类型（见下表）
result.getErrorMessage()  // 错误描述
```

| ErrorType | 含义 | 建议处理 |
|-----------|------|---------|
| `NONE` | 成功 | — |
| `DOWNLOAD_FAILED` | 下载失败（重试3次后） | 检查URL可访问性、网络 |
| `FILE_CORRUPTED` | 文件无效/损坏 | URL需认证或返回了HTML错误页 |
| `FILE_EMPTY` | 文件为空 | 服务端返回空内容 |
| `UPLOAD_FAILED` | 上传到页面失败 | DOM结构变更，检查选择器 |
| `UPLOAD_TIMEOUT` | 异步完成检测超时 | 文件仍在处理中，可根据业务忽略 |
| `BEFORE_ACTION_FAILED` | 上传前准备失败 | 检查 BeforeUploadAction 逻辑 |
| `UNKNOWN` | 未知异常 | 查日志排查 |

## 4. 设计思路与源码说明

### 4.1 为什么要单独封装这个工具？

在接入多个 AI 平台（DeepSeek、Gitee、元宝等）时，每个 Controller 都重复写了相同的「下载 → 上传 → 清理」代码，且各自没有重试、没有文件校验，下载失败时直接崩溃。

封装目标：
- **通用**：与具体平台解耦，通过函数式接口注入差异逻辑
- **健壮**：下载重试、文件校验、异常分类，每一步都有兜底
- **可扩展**：新平台只需实现 `PageFileUploader`，不需要改工具本身

### 4.2 核心设计：「工具只管送达，不管解析」

文件上传是一个**两阶段**的过程：
1. **送达**：将文件传递给页面（同步，可以确认）
2. **解析**：AI平台在后台处理文件（异步，不同平台行为完全不同）

本工具只负责第1阶段，第2阶段通过可选的 `UploadCompletionChecker` 开放给开发者自行决定是否等待、如何等待。

### 4.3 FileChooser 的正确使用方式

Playwright 的文件选择器有两种处理方式，工具使用的是**原子化**的 `waitForFileChooser`：

```java
// 正确：原子操作，点击触发后立即捕获
FileChooser fc = page.waitForFileChooser(
    () -> button.click()
);
fc.setFiles(filePath);

// 错误：onFileChooser 是永久监听器，会一直存在，导致后续点击也触发文件设置
page.onFileChooser(fc -> fc.setFiles(filePath));
button.click();
```

使用 `waitForFileChooser` 确保监听器用完即销毁，不会污染后续操作。

### 4.4 多步骤上传的设计（uploadViaSteps）

部分平台的上传入口隐藏在多级菜单中，单纯查找 `input[type=file]` 无效。
`uploadViaSteps` 的设计思路：

```
准备步骤（UploadStep[]）         触发步骤
┌─────────────────────────┐     ┌───────────────────────────────┐
│ 步骤1：点击附件按钮      │────>│ waitForFileChooser({          │
│ 步骤2：等待菜单展开      │     │   trigger.click()             │
│ 步骤3：...               │     │ }) → setFiles(filePath)       │
└─────────────────────────┘     └───────────────────────────────┘
```

前置步骤失败**不中断**，只记录日志——因为某些步骤（如等待）本身就可能不稳定，不应因此放弃整个上传。

### 4.5 DOM 上传的三级降级策略

`uploadViaDOM` 按以下优先级依次尝试：

```
① input[type=file]（最直接）
     ↓ 找不到
② 自定义选择器（开发者提供，平台特有）
     ↓ 全部失败
③ 内置通用选择器（中英文上传按钮）
   - button:has-text('上传') / button:has-text('Upload')
   - [aria-label='上传文件'] / [aria-label='Upload file']
   - div.upload-trigger / button.upload-btn / button.attach-btn ...
     ↓ 全部失败
  返回 false，调用方决定下一步
```

### 4.6 文件校验的必要性

HTTP 请求返回 200 不等于内容是有效文件。常见的陷阱：

| 服务端行为 | 下载到的内容 | 不校验的后果 |
|-----------|-------------|-------------|
| 资源需要登录 | 登录页HTML | 上传了HTML文件，平台报错 |
| 文件已删除 | 404错误页HTML | 上传了HTML文件 |
| 网络中断 | 0字节文件 | 上传空文件，平台静默失败 |
| CDN限速截断 | 不完整的二进制 | 上传损坏文件 |

工具在下载后立即检查：文件大小、是否为HTML内容（读取文件头256字节判断）。
