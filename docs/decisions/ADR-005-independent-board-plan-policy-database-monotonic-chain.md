# ADR-005：以数据库单调链守卫补强计划策略回执与 head

## 状态

Accepted（W3k 本地候选，默认不改变产品策略或线上流量）

## 日期

2026-07-23

## 背景

ADR-004 已将策略变更建模为不可变回执加 CAS head，但 `public_init_039`
只能阻止回执的 `UPDATE` 与 `DELETE`。拥有直接 DML 权限的写入者仍可能插入跳版
回执、把 head 重指向历史版本，或删除并重建 head。应用层锁和 CAS 不能约束这类数据库
直写路径。

## 决策

保持 `public_init_039` 及其已审核字节不变，追加 `public_init_040`。后继迁移只增加
数据库级 `BEFORE` 触发器：

- 新回执必须以该套餐当前 head 为唯一前序，版本必须恰为 `head + 1`，前序回执 ID 与
  策略摘要必须精确匹配；
- head 只能在同一产品/套餐内从旧回执前进到该直接后继，不能跳版、回退或重指向；
- 完成基线后，head 不允许直接插入或删除；
- 现有应用的“先插入回执、再 CAS 更新 head、同一 InnoDB 事务提交”仍是唯一受支持的
  写入顺序。

触发器使用 `SIGNAL SQLSTATE '45000'` 失败关闭。迁移只在 MySQL Community 8.0.30 与
8.4.8 的精确双版本矩阵中接受，并保留 039 的历史回归与元数据边界。

## 不在本决策中解决的边界

触发器无法证明数据库账号没有 `DROP TRIGGER`、DDL 或直接 DML 权限，也无法保证有权限的
恶意写入者不会构造一个语法正确的直接后继后故意不推进 head。生产权威化前仍必须完成：

- 应用运行账号收敛为仅可调用受控写入过程，撤销目标表直接写/DDL 权限；
- 受控过程或等效服务边界的调用者授权、命令签名与原子提交回读；
- 真实目标数据库的迁移、权限、回滚与回执验证。

因此 W3k 是数据库单调性加固，不是策略写入权限收敛完成，更不是生产激活授权。

## 后果

- 039 的冻结历史、26.7.20 专家包和既有 HTTP/UI 默认关闭状态均不改写；
- 直接 DML 的跳版、回退、head 删除/重建和错误前序摘要会在数据库层失败；
- 初始化器、manifest、真实 MySQL 双版本回归和当前读必须把 040 作为独立后继版本验证；
- 迁移成功不证明线上部署、最小权限或自然业务流量。
