# W3k：独董会计划策略数据库单调链合同

## 目标与冻结边界

本纵切在不修改 `public_init_039`、不修改已提交审核的独董会 26.7.20 专家包、不开启任何
菜单、HTTP 路由、候选开关或生产切流的前提下，补齐策略回执与当前 head 的数据库级单调链
约束。唯一新增公开迁移为 `public_init_040`。

## 写入合同

对 `FBSIR_INDEPENDENT_BOARD` 的每个 `BOARD_FREE` 或 `BOARD_VIP` 套餐：

1. 新 `fbs_plan_policy_revision_receipt` 必须以当前 head 指向回执作为前序；
2. `policy_version` 必须严格等于当前 head 版本加一；
3. `previous_receipt_id` 与 `previous_policy_digest` 必须与该当前回执逐字节一致；
4. `fbs_plan_policy_head` 的产品、套餐与创建时间不可改变，版本只能加一，且新 head 必须
   指向上述直接后继；
5. head 基线已由 039 创建，040 后禁止直接 `INSERT` 与 `DELETE`；
6. 任一违例必须以 SQLSTATE `45000` 失败，且不得留下新回执或 head 状态变化。

040 自身和初始化器都会先逐字节核验 039 的七个触发器体、两条固定基线回执和两行 head
目录；仅允许 039 完整态或由四个已知 W3k 守卫构成的 8、9、10、11 触发器加性集合。任何
其他前序漂移均失败关闭。

受支持的应用事务顺序保持为：锁定 head 目录与当前策略、验证命令、插入 `N+1` 回执、以
旧回执/旧版本 CAS 更新 head、在同一 InnoDB 事务提交。回滚也是新的 `N+1` 补偿回执，不得
让 head 倒退。

## RED/Green 矩阵

实现前的真实 MySQL RED 必须证明 039 单独允许以下错误直写；040 后每项均失败关闭：

- 直接插入 `N+2` 或 `N+99`；
- 插入前序回执 ID 或前序策略摘要错误的 `N+1`；
- 把 head 指到历史回执、跳版回执或不同套餐回执；
- 直接删除 head，或删除后重新插入 head；
- 成功的正常修订、补偿回滚、039 历史回归、当前读取和操作策略谱系不得回归。

矩阵必须在 MySQL Community 8.0.30 与 8.4.8 各执行一次，包含首次应用、完整态重放、
8/9/10 触发器集合的原始 SQL 与 `public_init_040` RUNNING 初始化器续跑、039 触发器
字节/元数据漂移拒绝及服务端 20 轮并发回归。

## 权限边界

本合同不声称触发器能约束拥有 DDL 权限或任意直接表写权限的数据库主体。生产激活前，
必须另行取得最小权限、受控写入过程（或等效服务边界）、目标库回读、发布目标 commit、
人工审批和回滚证据；缺任一项时保持默认关闭。
