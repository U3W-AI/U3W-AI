# 独董会积分账本宿主升级需求

## 1. 结论

现有 WorkBuddy/专家端若仍调用 `POST /fbs/skill-api/points/earn`，需要在下一版本升级。该旧入口允许客户端选择用户、规则来源和积分数量，已在服务端固定关闭为真实 HTTP `410 Gone`，错误码为 `SKILL_POINTS_EARN_DISABLED`。本需求不修改已提审并冻结的 `fbsir-eight-seat-board@26.7.20`。

## 2. 下一版宿主必须实现

1. 收到 `410` 后停止重试，不得回退调用 `/points/changePoints` 或本地直接修改余额。
2. 只上报服务端预先登记的行为代码和客户端生成的唯一请求 ID；不得上报积分数量。
3. API Key 必须绑定真实用户与宿主实例；请求体中的用户 ID 仅可作为一致性校验字段，不能作为身份真源。
4. 每次请求带产品代码、宿主版本、专家包版本、安装/设备摘要、发生时间与一次性随机数，服务端据此形成请求摘要并做同键同摘要幂等。
5. 显示服务端返回的已提交账本回执；超时只能用同一请求 ID 查询或重试，不能生成新的增发请求。
6. 在新写合同正式切流前，积分任务入口保持隐藏或只读说明。
7. `usageRecordId` 必须在用户、场景包、技能和宿主范围内稳定且不可跨范围复用；命中不同范围时将收到 `SKILL_USAGE_RECORD_SCOPE_MISMATCH`，宿主必须停止重试并生成新的业务操作。

当前运营侧生成但 `userId=null` 的 API Key 不能调用 `rights/check`、`usage/consume`、`usage/start`、`usage/end` 或 `user/info`；下一版应改用用户自助生成的绑定 Key，或先完成受审计的绑定流程。

## 3. 服务端配套门槛

- 服务端根据受版本控制的规则计算增减值，调用方不能传最终金额；
- 账户真源为 `USER_GLOBAL/FBS_POINTS`，租户、成员、产品、版本仅作为操作时快照；
- 操作 ID 与请求摘要唯一绑定，冲突必须失败关闭；
- 余额更新与不可变 operation/entry 写入同一事务并使用锁定读；
- 只允许追加，数据库阻止 operation/entry 的更新和删除；
- 首波只开放只读审计，旧写方全部适配且完成对账前不晋级为权威真源。

## 4. 验收

需同时提供宿主版本、请求/回执摘要、同 ID 同范围重放、跨用户/跨包/跨技能/跨宿主范围冲突、异摘要冲突、断网重试、跨用户伪造、并发请求和服务端余额/账本一致性证明。没有这些证据时，保持 `not_proven`，不得恢复旧积分写入口。
