`docs/independent-board/prototypes/portals/index.html` 是一个单文件 HTML 粗粒度示意：
- 内联 CSS+JS，约 66 行
- me/admin 双模式切换（仅切换标题，无实际内容切换）

### 1.4 核心问题诊断

| # | 问题域 | 具体表现 | 影响 |
|---|---|---|---|
| P1 | **信息架构单薄** | me 仅 1 个页面，admin 缺运营总览，W4 规划的"连接与授权""安全回执"等页面无任何 UI 雏形 | 用户无法形成清晰导航认知 |
| P2 | **视觉识别度低** | 独董会页面基本依赖 Element Plus 默认样式，品牌色仅 Hero 渐变区使用 #246bfd，整体缺乏品牌差异化 | 与普通若依后台难以区分 |
| P3 | **状态传达不足** | Connector 状态仅有文字标签，VIP 激活流程虽有 3 步描述但无动态进度指示 | 用户对"当前在哪一步"缺乏直觉感知 |
| P4 | **数据展示单一** | 全部使用 `el-table` 平铺，admin 无图表、无趋势、无下钻入口 | 运营数据洞察力不足 |
| P5 | **空态/加载态粗糙** | 加载用 `el-skeleton :rows="8"`，空态用 `el-empty` 默认样式 | 首次使用体验差 |
| P6 | **移动端体验割裂** | me 页面 768px 断点降为单列但保留若依侧栏，admin 表格无横向适配方案 | 小屏不可用 |
| P7 | **无引导/无帮助** | 新用户无 onboarding，OAuth 同意页虽有设计规范但无实际 UI | 用户首次使用门槛高 |
| P8 | **原型与实现差距大** | 静态 HTML 原型与实际 Vue 页面在信息密度、布局、配色上差异明显 | 沟通成本高 |

## 二、设计目标与原则

### 2.1 三大目标

1. **用户体验良好**：每个页面在 3 秒内传达"我在哪、能做什么、下一步是什么"
2. **功能完整**：覆盖 PORTAL-PROTOTYPE-SPEC 第 4 节规划的全部页面，W4 原型页面有完整 UI 雏形
3. **视觉感受好**：建立独董会专属设计语言，与品牌"福帮手/FBSir"形成统一识别

### 2.2 设计原则

| 原则 | 含义 | 应用 |
|---|---|---|
| **安全优先** | 状态、回执、权限永远不骗用户 | 不用乐观 UI，不猜测 UNKNOWN，危险动作物理隔离 |
| **品牌一致** | 所有独董会页面使用同一品牌层 → 产品层 → 页面层结构 | Hero/卡片/弹窗/空态统一品牌色和文案 |
| **渐进披露** | 先展示摘要，再展开细节 | 卡片摘要 → 点击展开 → 弹窗/抽屉详情 |
| **状态驱动** | 每个状态都有明确的视觉语言 | 颜色+图标+文字三位一体，不只靠颜色 |
| **可复用** | 建立组件库，减少重复代码 | 状态卡、品牌 Hero、安全弹窗、空态插画等 |
| **响应优先** | 移动端不是降级而是平等体验 | 先设计移动布局，再增强桌面 |

## 四、me.u3w.com 改善方案

### 4.1 信息架构升级

**当前**：仅 1 个首页，所有信息堆叠在一个页面

**改善后**：保持单页应用，但引入"视区"概念，首屏横向分区：

```
┌─────────────────────────────────────────────────────┐
│ 品牌区（Hero）                                        │
│  福帮手 FBSir / 独董会 / 当前企业                      │
├──────────────┬──────────────┬──────────────────────┤
│ 权益状态卡    │ 额度进度卡    │ VIP 激活引导卡         │
├──────────────┴──────────────┴──────────────────────┤
│ 会议区                                               │
│  [预约入口]  [最近会议列表]                            │
├──────────────────────────────┬──────────────────────┤
│ 后续能力预告                   │ 帮助与安全             │
│  Watch | Webhook | 积分       │  安全回执 | 帮助中心    │
└──────────────────────────────┴──────────────────────┘
```

### 4.2 Hero 区重设计

**当前问题**：Hero 虽有渐变但品牌层、产品层、上下文选择器混在一起，视觉层次不清晰。

**改善方案**：

```text
┌─────────────────────────────────────────────────────────────┐
│  [福]  福帮手  FBSir                    ┌──────────────┐   │
│        独董会                          │ 当前企业      │   │
│        把关键议题交给一组独立视角        │ [下拉选择 ▾]  │   │
│        在有限时间内形成可执行结论        │ [刷新]        │   │
│                                        └──────────────┘   │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 当前方案: 免费版  |  待连接 VIP  |  今日 0/1 次      │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

关键改善：
1. **品牌锁扣更紧凑**：品牌 mark + 品牌名 + 产品名三行竖排，层级清晰
2. **状态条内嵌 Hero**：在 Hero 底部增加一条半透明状态条，聚合展示方案、连接、额度三个关键状态
3. **上下文面板独立化**：企业选择器不再与品牌平级，而是放在 Hero 右侧独立卡片中
4. **背景增强**：在渐变基础上叠加微弱的品牌几何图案（SVG pattern），增加质感

### 4.3 状态卡片区升级

**当前**：三张等宽卡片，信息扁平。

**改善方案**：改为 1.2fr + 0.9fr + 0.9fr 不等宽网格，每张卡片增加：

**权益卡**：
- 顶部增加激活进度环（环形 SVG 进度条，展示 VIP 激活 2/3 步）
- 方案名使用 27px 粗体，下方紧跟"实际生效方案"标注
- 待连接状态：黄色脉冲呼吸动画提示用户注意
- 已撤销状态：红色描边 + 禁用图标

**额度卡**：
- 大数字展示剩余次数（34px 粗体），"/ 每日上限"用辅助色
- 进度条增加颜色阈值：<50% 蓝色、50-80% 黄色、>80% 红色
- 增加"已使用""已预留"双指标
- VIP 额度解锁提示：进度条上方显示"VIP 生效后提升至 5 次/日"

**引导卡**：
- 从静态文案改为动态步骤引导
- 步骤 1（已完成）✓ → 步骤 2（当前）脉冲 → 步骤 3（未解锁）灰色
- CTA 按钮颜色跟随步骤状态：蓝色（待处理）→ 绿色（已完成）

### 4.4 Connector 状态可视化

新增一个**连接器状态条**组件，位于 Hero 与摘要卡之间：

```text
┌───────────────────────────────────────────────────────────────┐
│  ●━━━━━━━●━━━━━━━○━━━━━━━○                                  │
│  授予VIP   待连接    激活中   VIP生效                            │
│  ✓ 完成    ● 当前    ○ 未到    ○ 未到                            │
│                                                               │
│  下一步: 在 WorkBuddy 中完成 OAuth 授权                         │
│  [了解连接流程]  [返回 WorkBuddy]                               │
└───────────────────────────────────────────────────────────────┘
```

实现细节：
- 使用 SVG 绘制 4 节点水平时间线
- 已完成节点：实心圆 + 品牌绿 + 对号
- 当前节点：实心圆 + 品牌蓝 + 脉冲动画
- 未来节点：空心圆 + 中性灰
- 节点间连线：已完成段实线绿，未完成段虚线灰
- 底部显示"下一步"提示文字和行动按钮
- 在 UNKNOWN 状态下显示问号图标和"刷新查看状态"按钮

### 4.5 会议区域优化

**当前**：`el-table` 平铺，缺少视觉吸引力。

**改善方案**：

**预约入口增强**：
- 将"预约会议"按钮从卡片内移到独立的预约引导区
- 增加快速预设：[1 议题] [3 议题] [5 议题] 一键选择
- 预约弹窗增加议程预览：展示"预约后将减少今日 1 次额度"的可视化

**最近会议列表改造**：
- 桌面端保持表格，但增加行内状态色条（左侧 3px 色条标识状态）
- 每行增加"查看详情"icon button
- 空态替换为插画式空态："还没有会议记录，预约第一场独董会吧" + 引导按钮

### 4.6 后续能力区域重设计

**当前**：两张并排卡片，仅显示名称 + COMING_SOON 标签。

**改善方案**：

改为三列能力预告卡片，每张卡片包含：
- 顶部图标区（48px 圆角方块，品牌色浅底）
- 能力名称（14px 粗体）
- 一句话描述（12px 辅助色）
- 底部标签：`后续能力` / `规划中` / `即将推出`
- Hover 时卡片轻微上浮 + 阴影加深

三个能力：
1. Apple Watch（蓝色调）— "云上资产的轻量操作入口"
2. Webhook 订阅（绿色调）— "会议进展与独董会内参推送"
3. 福帮手积分（橙色调）— "能力解锁与产品流水"（新增加，对齐 SPEC 第 4.1 节第 5 项）

### 4.7 预约弹窗 UX 优化

**当前问题**：
- UNKNOWN 状态处理优秀（安全回读），但表单交互粗糙
- 议题/席位使用 `el-input-number`，用户需点击上下箭头
- 缺少额度预览和结果预演

**改善方案**：

1. **分段式预约流程**：将弹窗分为"议程"→"确认"两步
   - 第一步：选择议题数和席位数，右侧实时展示"当前剩余额度"和"预约后剩余"
   - 第二步：确认信息摘要，展示操作编号和安全提示

2. **数字选择优化**：议题/席位改为按钮组选择
   - 议题：[1] [2] [3] [4] [5] ...（上限由方案决定）
   - 席位：[1] [2] [3] [全部]（全部=方案上限）

3. **安全提示卡片化**：将"预约成功后今日剩余额度将减少 1 次"从 Alert 改为信息卡

4. **UNKNOWN 状态增强**：保留现有安全回读机制，但增加"查看当前预约状态"的进度可视化

- 套餐选择从 Radio 改为卡片选择
- 截止时间增加快捷选项：[7 天] [30 天] [90 天] [永久]
- 增加"授予后影响预览"：展示"该成员将从免费版升级为 VIP 版，额度从 1→5 次/日"

### 5.3 回执审计与会议审计统一

**当前**：两个独立页面，各自有独立的筛选表单和分页。

**改善方案**：保持两个独立页面，但统一交互模式：

**筛选区**：
- 筛选表单改为可折叠抽屉式（默认展开，可一键收起）
- 增加常用筛选预设：[今日] [本周] [本月] [全部]
- 筛选结果实时更新，不触发页面跳转

**表格**：
- 统一行高、列宽和对齐方式
- 增加行 hover 高亮 + 左侧状态色条
- 表头增加排序图标
- 审计表格增加"复制操作编号"快捷按钮

**截断提示优化**：
- 将截断 Alert 从页面顶部移到表格上方，更贴近上下文
- 增加"仅显示前 N 条"的微缩标签

### 5.4 W4 原型页面 UI 雏形

按 SPEC 第 4.2 节，admin 需新增 4 个 W4 只读页面。建议在原型阶段提供完整 UI：

**OAuth 客户端页**：
- 筛选区：状态、注册时间、到期窗口、redirect 端口
- 表格：客户端缩略 ID、名称、状态、redirect、四项 Scope、注册/到期时间、版本
- 详情抽屉：metadata digest 与 source digest 缩略值

**Token Family 页**：
- 筛选区：状态、企业/成员
- 表格：family 缩略 ID、安全标签、client、consent intent、状态、generation、binding、时间线、版本
- 状态色条：PENDING_BINDING=蓝、ACTIVE=绿、REVOKED=红、COMPROMISED=深红、EXPIRED=灰

**Connector Binding 页**：
- 筛选区：状态、企业
- 表格：binding 缩略 ID、企业/成员、产品、source、connector、状态、Scope、验证方法、时间线、版本
- 业务标签列：仅当 `ACTIVE + exact scopes + active family + active entitlement` 才显示"VIP 连接已生效"

**安全事件页**：
- 筛选区：action 类型、时间范围、actor type
- 时间线视图：默认以时间轴展示，可切换为表格视图
- 每条事件：时间、action、actor、缩略 lineage、correlation、evidence level、reason code
- 事件类型分组：授权 / family / binding / 风险

### 5.5 危险动作视觉规范

所有危险动作（撤销权益、撤销 family/binding）统一模式：

1. **按钮样式**：红色文字 + 红色边框，hover 时红色背景
2. **确认弹窗**：使用 `ElMessageBox` 自定义内容
   - 顶部红色图标 + 标题
   - 中间影响范围列表（每项带 checkbox，但默认全选且不可取消）
   - 底部 reason code 下拉选择
   - 二次确认输入框（输入"确认撤销"才可提交）
3. **提交中**：按钮 loading + 全局遮罩
4. **成功回执**：绿色结果卡 + 操作编号 + 时间
5. **未知结果**：黄色待核验卡 + "请勿重复提交" + 手动刷新按钮
