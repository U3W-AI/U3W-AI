# 依赖安全维护

> 更新日期：2026-07-11

## 目标

前端依赖必须由 `FBSir-ui/package-lock.json` 精确锁定，并在每次依赖变更后完成审计和生产构建。这样可以让本地安装、持续集成与 GitHub 的依赖图使用同一份可复现的依赖清单。

## 日常维护步骤

在 `FBSir-ui` 目录执行：

```powershell
npm ci
npm audit --audit-level=low
npm run verify:svg-icons
npm run build:prod
```

依赖升级完成后，应提交 `package.json` 与 `package-lock.json`，不要只提交其中一个文件。若审计提示不能自动修复的问题，先确认受影响包是否位于运行时路径；不要以 `--force` 或无依据的版本降级掩盖风险。

## 自动防回归

- `.github/dependabot.yml` 每周检查 `FBSir-ui` 的 npm 依赖，并将非主版本更新分组提交。
- `.github/workflows/dependency-security.yml` 在前端依赖或 Vite 构建链变更时执行锁定安装、依赖审计、SVG 图标契约验证和生产构建。
- `vite-plugin-svg-icons` 已由仓库内的 `vite/plugins/svg-icon.js` 替代。该实现保留 `virtual:svg-icons-register` 与 `#icon-图标名` 的既有组件接口，避免引入已无安全修复版本的构建链依赖。

## GitHub 告警处理原则

代码路径或锁文件发生迁移后，GitHub 的依赖图重新计算可能需要短暂时间。先推送当前 `package.json` 和锁文件，确认默认分支的依赖图已刷新；只有仍与当前清单对应的告警才进入逐项修复。不要为了清空历史路径告警而直接忽略或误标已关闭的安全问题。
